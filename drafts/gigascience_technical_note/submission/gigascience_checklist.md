# GigaScience Technical Note checklist

## Article structure

- [ ] Structured abstract contains Background, Findings and Conclusions and is
      no longer than 250 words.
- [ ] Three to ten keywords are present.
- [ ] Findings describe implementation, availability, testing and limitations.
- [ ] Methods allow an expert to interpret and reproduce the work.
- [ ] Software requirements, license, version, RRID and bio.tools ID are listed.
- [ ] Data Availability cites permanent identifiers.
- [ ] Abbreviations and all declaration sections are present.

## Reproducibility

- [ ] Source code is openly available under the declared OSI-approved license.
- [ ] The exact manuscript version is archived with a DOI or Software Heritage
      identifier.
- [ ] Test input, expected output and execution instructions are freely
      available to editors and reviewers.
- [ ] Benchmark source tables, manifests, comparators and rendering code are
      deposited under a persistent identifier.
- [ ] Software, datasets and workflows are cited as research objects.

## Files and declarations

- [ ] Editable DOCX or TeX source is uploaded.
- [ ] Figures are uploaded separately in accepted high-resolution formats.
- [ ] Every additional file is cited sequentially and its name includes
      “Supplementary Material” where required.
- [ ] The cover letter explains utility, reproducibility and journal fit.
- [ ] All authors approved the submission and its author order.
- [ ] Competing interests, funding and related submissions are disclosed.
- [ ] AI-assisted drafting is disclosed with tool, model family, date and
      directing author.
- [ ] The current online author instructions are rechecked on submission day.
